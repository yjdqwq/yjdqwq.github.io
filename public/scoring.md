# 题评评分标准 v1.2

更新日期：2026-11-03。本次按比赛选题的适用性重新定义竞赛分档，并将纯模板的竞赛评分基准设为 −6，上下浮动。评分使用 −10～+10 的整数，未评分没有分数；理由、标签和剧透均为选填，只打分也正常计票。

## 竞赛出题质量

竞赛评分回答：**作为面向目标参赛者的比赛题，它值得被选用吗？** 结合比赛背景、题位和受众评价，不把第一次见到某种方法的惊喜直接当成出题质量。0～+2 只表示勉强可以放进比赛，尚不算值得推荐的好题。

| 分数 | 含义 |
|---|---|
| −10～−9 | 绝世⑩题：极端糟糕的设计或比赛体验，保留给最严重的情况 |
| −8～−6 | 绝对不能放进比赛的题 |
| −5～−3 | 完全没意思的题目 |
| −2～−1 | 没意思的题目 |
| 0～+2 | 勉强可以放进比赛 |
| +3～+5 | 好题：结构收益清楚，线索、证明和实现相称 |
| +6～+8 | 优秀：核心发现与模型结合突出，值得推荐 |
| +9～+10 | 极优秀：充分理解与比较后，仍是难得的设计 |

这是本站约定的主观质量尺度，不是题目难度、比赛分值或其他平台评分的换算。分档讨论题目，不攻击作者。

## 纯模板：以 −6 为基准上下浮动

纯模板指直接复现已有的标准算法或模型，题目本身缺少实质性的观察、转化、组合或取舍。**作为比赛题，纯模板默认以 −6 为基准，再按照搬程度、包装与完成负担上下浮动。** 首次接触某个经典模板时的个人惊喜，不会自动提高它的出题质量。

使用经典算法或 trick 不等于纯模板。若识别结构、完成转化或组织方法本身产生了有价值的发现，仍按其实际收益评价。历史上首次提出的方法，也应结合当时的知识背景判断。不能只凭题目标题带有“模板”、算法名称、代码长度或自己是否见过直接判分。

简单而有内容的题可以是好题；只是更难、更长的模板仍可能缺乏比赛价值。工具训练价值应另计入学习训练用途。

## 学习训练另行评价

学习训练评价理解路径、方法展示和练习收益，**以 0 为同用途的一般题**。模板题可以很适合教学，不套用竞赛的 −6 基准。竞赛与学习训练的评分分别汇总，不相互混合。

学习训练沿用：−10～−9 极差，−8～−6 很差，−5～−3 较差，−2～−1 略差，0 一般，+1～+2 稍好，+3～+5 好题，+6～+8 优秀，+9～+10 极优秀。

## 如何评价

总分由评价者整体判断，不从多个维度机械加权。不要求为打分凑字数；愿意补充时，可以选择最有把握的内容：

1. **结构收益：**关键观察消除了哪些枚举、状态或依赖？是题目特有的转化，还是只需复现通法？
2. **完成成本：**读题、证明、分类和实现负担，换来了什么收获？比较合理完整解法，检查是否有更简洁的表示，不能按树、数组或代码行数计罚。
3. **比赛适用性：**对目标参赛者而言，题目有什么值得探索的内容？它是否适合该题位与比赛背景？难度、熟悉程度和一次解题是否顺利分别记录。
4. **表达与可用性：**定义、样例、资源余量、数据与部分分是否合理？题面形式化本身不扣分；具体歧义、无益约定和比赛障碍才计入成本。未核验的风险标明未知。

经典技巧的有效化简可以带来正分；缺少思维和算法内容、主要剩下机械维护的做法应认真评估其比赛价值。多个工具也可以构成统一机制，不按工具种类一概扣分。明确的题面错误、数据错误、判题漏洞或时限问题，应另附可复核材料，设计分不代替可用性检查。

## 用途、经历和题目版本

提交总评分需自报“独立完成”或“参考题解并理解完整做法”。这是经历自报，不是 AC 认证，也不以 CF rating 赋予额外票权。只读过题面时，可以提交普通问题反馈，暂不计入质量均分。作者、验题者如参与评价，应在理由中披露关系。

每个 GitHub 账号、每个题目版本、每种用途只计一条有效评分，取最后更新的一条。修订后的题目建立新的版本标识，不把旧评分自动迁入。初始 `public-v1` 是本站建档标识，不表示完整存档了原题内容；外站链接可能变化。

清单内可以直接打分，草稿自动保存。解题经历可统一设置默认值，也可逐题调整。最后将本批已打分题目合并提交，未打分题目跳过；公开提交仍需在 GitHub 确认。内容过长时自动拆为少量几份。每批按单题展开并去重，与旧的单题记录使用相同票权。编辑整批会更新其中所有评分；关闭或排除整批会撤回本批记录，较旧记录不会因此恢复，更新的其他记录不受影响。

## 展示与汇总

同时展示均值、中位数、有效人数及 −10～+10 全分布，保留分歧。均分保留一位小数，只是样本摘要。零人评分显示“待评”，真实零分照常计入。

同用途下有 1 个有效账号评分即显示分数并进入榜单；零人不进入榜单。单人分数代表该评价者的判断，不代表社区共识。可切换只看独立完成者，样本人数随筛选重新计算。

使用 GitHub Issues 留存公开、可编辑的记录。关闭自己的评分 Issue 即撤回；管理员可关闭或添加 `rating:excluded` 标签排除不合规记录。账号只能抑制重复投票，无法完全阻止小号和协同刷分；管理员应公开说明排除原因。不同意见和极端分不按是否接近 AI 分决定可信度。

## 历史评分与参考

本版标准用于新的质量判断，历史人类评分没有自动换算。修改自己的分数请编辑对应 Issue；撤回可关闭 Issue。历史记录对应的判断背景，可在理由中说明。

[反馈校准页](feedback.html)保留 v1.1 标准下的固定快照，展示当时的原始评语、归纳和分歧；它不是当前 v1.2 分档的定义，已撤回记录也不作为当前有效投票。只有分数、没有文字理由的历史评价，不能由分析者补写动机。

[AI 参考评分](ai-anchors.html)保留 2026-10-26 的 206 条历史初评，尚未按本版逐题重评。AI 参考仅用于竞赛体验，独立存储和展示，不计入真人均分、人数、分布或榜单；可隐藏分数与折叠理由。没有充分材料时不伪造新版分数，不把人类均分复制成 AI 复评分。

本站参考 QOJ 的反馈展示、USACO Rating 社区项目的质量／难度分离，以及 Qingyu 的 UCup 评审随笔。本分档、模板基准、用途划分和汇总流程是本站约定，不冒称其他平台标准。资料边界见[研究记录](RESEARCH.md)。
