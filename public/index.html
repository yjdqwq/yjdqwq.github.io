SCORING STANDARD · V1.0

分数很短，理由可以更长。

−10～10 是整体质量判断。0 为同用途的一般题，未评分保持未知。

先选用途，再讨论质量

比赛里解题的体验，与用一道题学习新方法的体验，可以不同。本站将“竞赛体验”和“学习训练”分别统计；简单题、模板题、交互题，都按实际用途讨论。

21 个分数，9 个参考区间

总分由你判断，理由提供依据

01 / INSIGHT

洞察与趣味

关键观察改变了什么？是有意思的结构发现，还是普通的工具整理？

02 / MODEL

模型与自然性

规则是否共同服务于问题？通向经典模型的归约，也可以就是亮点。

03 / RETURN

完成成本与回报

阅读、证明、分类和实现的成本，换来了什么？有优点也可能整体得负分。

04 / EXPERIENCE

表达与可用性

定义、样例、部分分与资源设置是否合理？未检查的部分请保留未知。

这些是写评语的提示，不是自动加权公式。“正确、可解、能练工具”不足以自动获得正分；“难、长、用了某种算法”也不足以自动扣分。

每一条记录如何参与统计

  • 独立完成或参考题解并理解做法后，可提交总评分。经历为自报，本站不冒称 AC 认证。
  • 同一 GitHub 账号、同一题目版本、同一用途只计最后更新的一条记录。修改版本不沿用旧评分。
  • 显示均值、中位数、人数和完整分布。少于 5 人仍展示，但不进入榜单；5 人也不表示结果已具有统计可靠性。
  • 关闭最新记录可撤回该账号的评分。管理员可排除不合规记录，并应说明原因。账号限制不能完全防止小号刷分。
  • 剧透在详情里折叠展示。公开提交会保留 GitHub 身份；草稿只存在本浏览器。

RESEARCH NOTES · 2026.10.25

先看看别人，
怎样评价一道题。

借鉴已经存在的做法，也写清它们的适用边界。本站规则是独立的产品设计。

01
已实现的社区反馈

QOJ

用户的赞踩反馈与题目 Difficulty 分开展示。净票数反映反馈规模，不能直接换算成 −10～10 的质量分。

我们采用：质量与难度分开，样本规模随分数展示。
查看题库 ↗
02
独立的社区项目

USACO Rating

以 1～5 评价质量，以 800～3500 估计难度，由经审核用户投票，并提供均值／中位数视角。它不是 USACO 官方评分。

我们采用：分别收集质量与经历，保留分歧。
阅读项目 FAQ ↗
03
特定赛事的评审随笔

UCup 审题 rubric

Qingyu 将质量、难度、熟悉程度分别记录；有价值的题目也可能不适合某场比赛。作者明确说明这是一篇随笔。

我们采用：区分使用场景，分数附带简短理由。
阅读作者原文 ↗
04
官方命题方向

IOI 征题指南

欢迎简单与困难、富有创意且容易理解的题目，也鼓励有洞察、允许多种解法的简单题。

我们采用：题目难度、算法名称和代码长度不等于质量。
