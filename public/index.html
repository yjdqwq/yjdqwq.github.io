先选用途，再讨论质量

比赛里解题的体验，与用一道题学习新方法的体验，可以不同。本站将“竞赛体验”和“学习训练”分别统计；简单题、模板题、交互题，都按实际用途讨论。题目难度、平台标签、个人是否顺利做出，分别记录。

21 个分数，9 个参考区间

0 分可以包含清楚的观察、合理的证明、常规优化和工具训练价值。模板没有自动扣分，熟悉工具也没有自动加分；正分需要具体的额外亮点，负分需要具体的失衡。

判断收益，也看完成的成本

01 / INSIGHT

观察究竟带来了什么

说明它消除了哪些枚举、状态或依赖。区分题目特有的结构发现、非直接的方法迁移与常规整理；一个性质做完可以精彩，也可以只是一般题。

02 / MODEL

模型与方法是否贴合

规则和限制是否共同服务于核心问题？归约到经典模型可以就是亮点；条件都能写进算法，只说明可处理，还需要解释发现的价值。

03 / RETURN

发现之后，还要付出什么

分别看发现、证明与实现的回报。后续推导若持续产生结构收益，可以支撑高分；若主要剩下繁杂维护、分类或调参，需要衡量这份负担。

04 / ALTERNATIVES

不同解法提供了什么选择

比较真实可行路线的思维、代码和常数取舍。多解可以增加探索空间，但解法数量本身不加分；存在更简单满分做法时，按它重新检查评价。

05 / EXPERIENCE

惊喜、难度与质量分别看

“没想到”“做难了”是有用的体验记录。高难标签、熟悉程度或一次惊艳，不能单独决定质量；请指出值得保留的发现或不相称的成本。

06 / RELIABILITY

把可用性问题核实清楚

定义、样例、部分分与资源设置是否合理？卡常、非预期解和数据漏洞要附可复核依据；尚未核验时保留为反馈，不能当成已证实的缺陷。

这些是判断依据，不是自动加权公式。步骤多、代码长、使用高级算法都不自动加减分；同一个观察带来的多种好处，也不重复累计。

如何把反馈用于下一次评价

  • 分数与理由各自保留。仅有分数的记录照常计票，可用于分布和对照；没有写出的理由保持未知，不替评价者补上解释。
  • 原话与归纳分开。引用评语时保留作者、题目、版本、用途与来源。由多个案例推得的规则明确标为归纳，不把个人观点写成社区共识。
  • 分歧本身有信息。均值只是样本摘要，同时看每位评价者的分数、经历和原文。批量提交与单题提交同权，不因写了理由增加票权。
  • 校准仍需内容核验。已看过反馈后的重评属于回归检查。AI 原评分与人类反馈分别展示，不能把对齐分数当作独立预测，也不据此宣称准确率提高。

每一条记录如何参与统计

  • 独立完成或参考题解并理解完整做法后，可提交总评分。只打分也计票，理由为选填；经历为自报，本站不冒称 AC 认证。
  • 同一 GitHub 账号、同一题目版本、同一用途只计最后更新的一条记录。修改版本不沿用旧评分。
  • 显示均值、中位数、人数和完整分布。同用途下有 1 个有效账号评分即可进入榜单；零人显示“待评”。单人评分代表该评价者的判断，不代表社区共识。
  • 支持多题合并提交。编辑整批会更新其中所有评分；关闭或排除整批会撤回本批的最新记录，较旧记录不会因此恢复，更新的其他记录不受影响。管理员排除不合规记录时应说明原因；账号限制不能完全防止小号刷分。
  • AI 参考不计入真人均分、人数、分布或榜单。剧透在详情里折叠展示。公开提交会保留 GitHub 身份；草稿只存在本浏览器。

独立的社区项目

USACO Rating

我们采用：分别收集质量与经历，保留分歧。
